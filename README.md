# Trendoscope — Every Change Has a Story. Discover Yours.

A browser-based investigation tool built for the **NASA Space Apps Challenge Cairo 2026** challenge
_"Be An Earth System Trend Detective!"_.

A student with no statistics background picks a region on a map and a variable, and within a few
seconds sees whether that variable is really changing — a chart, a significance stamp, six statistics
and one plain sentence. Then they can follow the change to what causes it and what it affects, through
a comparison page and a detective game.

Everything is static: no build step, no server, no API key, and no network calls at run time.
All series are cached from **NASA POWER / MERRA-2** during a one-off download.

---

## Run it

Any static file server works:

```bash
cd trendoscope
python3 -m http.server 8000
# open http://localhost:8000
```

`index.html` also works when opened directly from disk (`file://`), because the cached data ships as
plain `.js` files rather than JSON fetched over HTTP.

Optional: a different port (`python3 -m http.server 8080`), or `npx serve .`.

## Deploy to Render

This project is a static site and needs no environment variables or dependency installation.
The repository includes a `render.yaml` Blueprint that publishes the project root.

1. Push the repository to GitHub.
2. In Render, choose **New → Blueprint** and connect this repository.
3. Review the `trendoscope` static site and deploy it. Render will use the default branch
   containing `render.yaml`; future pushes to that branch deploy automatically.

The site uses regular `.html` page URLs, so no single-page-app rewrite rule is needed.

### Dependencies

None to install. The site ships its own copies of:

- `vendor/plotly.min.js` — Plotly.js 2.35.2 (MIT), used for every chart

### The two home demos

1. **Spot the signal** — three sparklines: the real Sahel rainfall series, the same numbers in random
   order, and Gaussian noise with the same mean and spread. Pick the one you think is trending; the
   Mann-Kendall p-values are then revealed. It is the fastest way to show that shape is not evidence,
   order is.
2. **Where in the world** — click a pin on the map. One of the six regions has a strong, significant
   rise in root-zone soil wetness; every other pin reports its own slope and p-value, so a wrong guess
   still teaches something.

Both are computed at load time from the cached series, so they cannot drift from the rest of the site.

## Data

**Source:** NASA POWER (`power.larc.nasa.gov`), which serves the MERRA-2 reanalysis; precipitation is
bias-corrected with GPM/GPCP.

- Monthly: January 1993 – December 2024, `community=AG`, `format=JSON`
- Daily: January 2015 – December 2024
- Parameters: `T2M, PRECTOTCORR, GWETROOT, GWETTOP, RH2M, WS2M, EVPTRNS, ALLSKY_SFC_SW_DWN`
- Each region is a fixed latitude/longitude box; the cache stores the box average, its monthly
  climatology and the share of missing values.

Re-download (takes a couple of minutes, writes to `build/cache/`):

```bash
cd build && python3 build_data.py && python3 build_site.py
```

## Method

1. **Deseasonalise** — subtract each calendar month's long-term average, leaving anomalies.
2. **Theil–Sen slope** — median of all pairwise slopes; robust to outliers and breaks. A 95% interval
   is drawn as a fan around the trend line.
3. **Mann–Kendall test** — rank-based, tie-corrected; returns S, Kendall's tau, z and a two-sided p-value.
4. **Verdict** — p < 0.05 and rising → *significant increase*; p < 0.05 and falling → *significant
   decrease*; otherwise *no significant trend* (explicitly not "no trend").
5. **p-value picture** — the Ask panel can draw the distribution of slopes from shuffled copies of the
   series, with the real slope marked, so the meaning of a p-value is visible rather than asserted.

Rates are reported per decade (`slope × 12 × 10` for monthly data, `slope × 365.25 × 10` for daily).
On long daily records the pairwise slope set is deterministically subsampled (400k pairs) for speed and
the UI says so.

### Self-test

`data-method.html` can run three checks in your browser: a known ramp must recover its 6.00/decade
slope, pure noise must return p > 0.05, and shuffling a real series must destroy its trend. All three
pass in the shipping build; the measured values are printed on screen.

## Case scoring

The correlation between the evidence series and each suspect is computed at lags −6…+6 months; the
strongest lag is kept.

| Outcome | Points |
| --- | --- |
| Strong clue (|r| ≥ 0.5, within 0.1 of the best in the file) | 100 |
| Strong clue, but not the best | 80 |
| Weak clue (0.3 ≤ |r| < 0.5) | 40 |
| Red herring (|r| < 0.3) | 0 |

Stage 2 only reveals downstream effects whose |r| ≥ 0.2, strongest first, at most three. The wording is
always "associated with" — the app never claims causation.

## Accessibility and performance

- Keyboard reachable controls, visible 2px focus ring, skip link, `aria-pressed` on toggles and
  segmented controls, `aria-expanded` on the chat button, `role="log"` + `aria-live` on the chat.
- Map pins are real buttons: `tabindex="0"`, `role="button"`, `aria-label`, and Enter/Space activate
  them. The two Egyptian pins are nudged apart with leader lines so both stay clickable.
- Charts carry a text summary (`chart-alt`) and the tables/stat cards are real text.
- `prefers-reduced-motion` disables animations.
- No layout shift on chart load (fixed min-heights); monthly cache ≈ 100 KB, daily ≈ 1 MB loaded only
  when the Daily toggle is used.
- The mascot is inline SVG, so it costs no extra request.

## AI use

See `data-method.html#ai-use`. In short: AI assistance wrote and reviewed the code, drafted the
plain-language copy, and designed the interface and mascot. "Ask Trendoscope" is a deterministic answer
engine in this build — it assembles sentences only from the current result object and a fixed glossary,
with no language model call and no network request. No data was generated by AI.
